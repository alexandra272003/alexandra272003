<summary><b>01 · pycleanframe</b> &nbsp;·&nbsp; <i>Open-Source Python Library for DataFrame Cleaning</i> &nbsp;
<img src="https://img.shields.io/pypi/v/pycleanframe?style=flat-square&logo=pypi&logoColor=white&color=6C47FF"/>
<img src="https://img.shields.io/badge/MIT-License-22c55e?style=flat-square"/>
</summary>

<br/>

Published an open-source Python package on **PyPI** that simplifies DataFrame preprocessing using decorators.

Designed to eliminate repetitive data-cleaning code by providing reusable, configurable decorators for missing-value handling, normalization, validation, and preprocessing workflows.

```python
from cleanframe import cleanframe

@cleanframe(drop_nulls=True, normalize=["age", "salary"])
def process(df):
    return df.groupby("department").mean()
```

### Highlights

* Published on PyPI
* Decorator-based API
* Reusable preprocessing pipelines
* Data validation & cleaning
* Lightweight and production-friendly

`Python` · `Pandas` · `Decorators` · `Open Source` · `PyPI`

Seven projects built back to back during a backend + GenAI interview sprint — each one adds a layer the last one deliberately left out, ending in a multi-tenant RAG platform.

<!-- 08 -->

<details>
<summary><b>08 · Multi-Tenant RAG Platform</b> &nbsp;·&nbsp; <i>Capstone: Isolated, Cited Q&A for Many Organisations</i> &nbsp;
<img src="https://img.shields.io/badge/Postgres-Row--Level%20Security-06B6D4?style=flat-square&logo=postgresql&logoColor=white"/>
<img src="https://img.shields.io/badge/pgvector-RAG-A855F7?style=flat-square"/>
</summary>

<br/>

A document + RAG platform where organisations upload documents, a background worker ingests them, and users ask grounded, cited questions in chat — built around what makes RAG trustworthy to run for several customers at once: isolation, authorization, failure-tolerant jobs, quotas and observability.

### Highlights

* **Tenant isolation in three independent layers**, including Postgres row-level security; another tenant's ids return `404`, never `403`
* JWT auth with owner / admin / editor / viewer roles, plus separate object-level checks (an editor edits only their own documents)
* Async ingestion: `POST /documents` → `202`, then a Celery worker parses, chunks, embeds and publishes (`uploaded → processing → ready | failed`)
* Tenant- and visibility-filtered pgvector retrieval; cited answers where every citation is checked against what was actually retrieved, and no LLM call when there's no evidence
* Conversational RAG, a tool-calling agent with a guarded read-only SQL tool, and schema-validated structured output
* Per-tenant daily quotas and rate limits, Prometheus metrics, JSON logs with request/tenant/user IDs, append-only audit log, soft delete and optimistic locking
* Documented verification: 468 unit/API tests, 57 real-Postgres checks (RLS, migrations up/down/up, concurrency) and 31 end-to-end checks — plus a plain-spoken "known limitations" section

`Python` · `FastAPI` · `PostgreSQL` · `pgvector` · `Celery` · `Redis` · `LangChain` · `Alembic` · `Prometheus` · `Docker`

🔗 [View repo](https://github.com/alexandra272003/multi-tenant-rag-platform)

</details>

A desktop app that hides secret text, files or voice messages inside images using **LSB steganography**, with optional AES-256-GCM encryption of the hidden payload.

### Highlights

* Password-derived keys via PBKDF2-HMAC-SHA256 (200,000 iterations)
* Capacity check before encoding, and a before/after comparison with computed **PSNR** to quantify how invisible the change is
* Self-verifying output: after saving, the engine re-reads the image and deletes the result if the hidden bits didn't survive
* Voice messages: record, transcribe (online or offline with Vosk) and hide the transcript or the recording itself
* Separated core engine and GUI; NumPy-vectorised so large images stay fast

`Python` · `NumPy` · `Pillow` · `Tkinter` · `Cryptography`
